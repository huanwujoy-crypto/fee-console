## 2. 固定方法

| 方案 | 定义 |
|---|---|
| A 实际 | IB既定资产范围＋NOAH-HK现金，排除GLD、SLV、MSTR、HODL；保留实际税费和利息 |
| B 建议模拟 | 与A同额，假设留存USD240000；余下股票部分CSPX60%、EXUS23%、EIMI12%、USSC5%、EQAC0% |
| C 标普500 | 与A同额全部模拟CSPX累积型，ISIN IE00B5BMR087 |

B不每日再平衡。留存只是比较假设，不证明CALL已足额或银行资金可用；C
全部股票，与B的风险不同。旧版逐步换仓B及旧账本保留。冻结日前B为虚线
回溯模拟，冻结后也仍是模拟，不是实际调仓。B/C不另估个人税费、交易成本
或现金利息；基金价格内费用不重复扣。不年化、不评分、不据短期差距判输赢。

每个业务日先计算表现，再记日终流量。A/B/C使用同一经济日期、唯一ID、
方向及USD金额的外部／跨范围现金事件。内部买卖、股息、费用、范围内转账
不算外部流量；主题范围内外转移必须计入，不能因为排除了标的便忽略本金。
正负事件先按当天净额匹配；原事件不删。入金先补B留存再按固定比例买入；
出金先用留存外现金，再按已有ETF比例减仓，耗尽ETF后才可动留存并提示。
不模拟借款。休市入金按真实日期进现金，下一共同真实收盘再模拟投资。

曲线从100开始，剔除日终流量影响逐日连乘；余额含新增本金，收益额另为
期末值减起点和累计净入金。最大回撤从同一流量调整曲线计算。

## 3. 来源及缺项

固定标的身份、USD币种、交易所收盘价格类型和逐标的真实价格日。A允许
注明时点的收盘后近似快照；不拿Sharesight历史界面中仍为当前值的现金倒填
历史IB现金，不混合不同时点凑数。近似不代表来源不明也可以填零。

输入日历逐日连续，周末也保留；每一天显式声明 actualComplete、flowsComplete，
附私密sourceRef和完整flows数组。上述标志是调用者的证据声明，计算器不会
自动证明金融来源真实／完整，维护者必须保留原始来源与对账。

行情只接受当日真实close、已知closed或missing。不得用未来价起算。意外缺价
最多暂估两个该市场交易日；闭市日不增缺价年龄。缺流量、缺A或超限停止延伸，
保留旧历史。暂估历史不能因下一天有价自动恢复为已核实，必须从起点完整重放。
手机展示最新共同完整数据日，历史估计段和回溯段用虚线。香港审批日期和
纽约业务日期分别核验，香港过午夜不能让未来纽约日提前成为数据日。

## 4. 私密显示及威胁边界

整份projection与金额result一同AES-256-GCM加密，不能仅把绝对金额加密后
公开相对曲线：已知固定现金留存可能反推财富。静态站点只接收密文，不发布
来源、原账本、真实输入或明文预览。正常报告既有公开字段不因此扩大范围。

必须使用独立、随机32字节的 XUAN_ETF_DATA_KEY；不复用fee分享链接的key、
GitHub token或旧账本commitment key。手机专用访问码不放URL、聊天、日志，
由用户一次性输入“ETF专属访问码”；认证解密成功后才存入
`xuan-etf:private-key:v2`。网页不会读取fee的key或上传访问码。

这提供静态存储加密，不是对合法数据生产者的端到端保密。手机localStorage
受同源脚本／XSS和设备访问风险影响，不能称硬件保险箱。源码及发布权限也
必须受控。丢失手机、怀疑泄露或主动撤销访问时，由用户确认轮换独立key、
重新加密和重新启用自己的设备；不能通过Git恢复明文key。旧密文一旦被持有
旧key的人取得，轮换不能追回其旧副本。

每次加密新随机96位nonce，固定用途AAD；方法、日期及逐行sourceRef在认证密文内。
这不是报告sourceSha/htmlBlob的独立绑定；来源真实性与完整性仍由生产核验负责。
固定生产 `--key-usage-root` 持久记录每key最多10000次尝试（失败也占额），
上限拒绝后必须手工轮换。不得每次新建计数根、删除记录或重置配额。
手机仅在认证后记录最大已见源日期，并拒绝更旧或未来的来源；跨标签页提交前
再读高水位。此机制不承诺同日修订的密码学防回滚，同日版本依赖受控Git发布。

离开页面会清掉已解密DOM并使在途请求失效；不持久缓存金融明文。不能承诺
清除操作系统截图、浏览器历史副本或已被用户复制的内容。模块失败只显示
“私密数据暂不可用”，不把旧数冒充更新，不影响其它可信报告。

## 5. 生产接入与发布

生产者复用早间报告的原始读取，整理成规范私密输入，不为ETF重取整份日报。
先核流量、身份和来源日，再从起点重放。既有原账本只读不变。专属key放受控
生产环境；调用builder时只通过环境变量传key，不放CLI参数。

```text
node scripts/xuan-ib-etf-trend-build.mjs
  --input <私密0700目录内的0600输入>
  --preview-root <独立私密0700预览目录>
  --key-usage-root <固定私密0700计数根>
  --envelope-out <新的密文输出路径>
```

明文输入／预览不得位于公开仓库；输出采用独占创建，不覆盖已有版本。
仅在生产验证和维护批准后，将合格密文按受控发布流程置于
`xuan-ib/etf-trend.enc.json`。当前builder不自动推送、替换固定文件、创建PR、
合并或配置真实Routine；不能声称只运行builder就已日常更新。

候选报告仍只改自己的index，canonical政策区和历史回执不动。已验证页面的
可选本地显示层可把私密ABC置前、将原政策及旧基线折叠到“原方案与历史基线记录”；
这不是重写latest文件，原始受控HTML和其blob保持不变。缺key／缺密文时原ETF
政策仍可读。没有交易或账本编辑按钮。

启用验收顺序：精确SHA批准／维护合并 → 专属key与固定计数根 → 源日期／流量
核验及首份密文 → Pages实际读回 → 真机首次启用／刷新 → 下一早间自动更新
及错误回退。未完成任一步应准确标为待验收，不发布伪造的零值或示例账户值。
