# XUAN-IB 香港时间报告契约 v1

> 本文件只规定报告时间、版次、日期语义与发布路径，不改变任何投资计算、持仓分类或风险参数；不授权下单、改单、撤单或转账。

## 1. 唯一调度时区

所有定时任务一律使用 `Asia/Hong_Kong`。香港全年为 UTC+8，无夏令时。美国夏令时（DST）、冬令时、休市或提前收市只改变报告内的市场阶段和数据截止说明，不改变香港发报时间。

## 2. 三种报告

| 版次 | 香港运行日与时间 | 用户含义 | 上线目标 | 独立看护 |
|---|---|---|---|---|
| `pm` 睡前版 | 周一至周五 20:55 | 当晚即时持仓、挂单、流动性、风险与市场阶段 | 21:15 前 | 21:25 检查 |
| `am` 早间版 | 周二至周六 08:00 | 前一个美国交易日收盘后的总结 | 08:20 前 | 08:35 检查 |
| `adhoc` 临时版 | 用户随时手动启动 | 以启动当时可取得的数据说明总体情况 | 通常 10–15 分钟 | 不代替 AM/PM 看护 |

周日没有新定时版；周一上午也没有新早间版。此时手机继续显示周六早间版或之后产生的合格临时版。美国休市日仍应发报告，明确写明“无新收盘数据”，不得静默跳过。

## 3. 报告日期与数据截止

- 报头日期是报告生成时的香港日期。
- 早间版另外明确写“对应美股交易日”或“美股休市，沿用最后可信收盘”。
- 每个主要来源分别标注 `as-of` 时间；不同来源时间不一致时不得假装同步。
- 美国市场状态必须由 `America/New_York` 时区和交易日历判断，不得按月份猜夏令时。
- 数据源失败时不得填零或猜数；按字段降级、保留上一份可信值并显著标注来源与日期。只有多个关键来源同时失效、无法确认账户范围，或候选 / Validate / Promote / Pages / 线上读回失败时，才按既有 fail-closed 规则停发。

### 3.1 IBKR 逐仓明细的批准回退（Wu 已批，2026-08-29）

`get_account_positions` 单一端点在有界重试后仍失败，属于**字段级数据源降级**，不得单独阻断 PM、AM、Run now、补跑或 ad hoc 报告的生成与发布。

1. 先确认 IBKR 的 account summary、balances、orders、trades 仍可只读，并记录逐仓端点的原始错误与重试次数。
2. IBKR 继续作为 NAV、现金、保证金、挂单和成交的权威来源；不得用 Sharesight 覆盖这些字段。
3. 逐仓数量、价格与市值可改读 Sharesight 的精确组合 `IB-HK`（portfolio id `936247`）。仅当其 `as-of` 不早于报告截止时已完成的最近一个美国交易日，或最多落后一个**已完成的美国交易日**时使用；周末与美国休市日不增加数据年龄。
4. 页面系统异常黄条、运行信息与页脚必须同时披露：`Sharesight IB-HK 逐仓替代`、IB 与 Sharesight 各自 `as-of`、相差几个已完成交易日、逐仓端点原始错误 / 重试次数、IB NAV 与 Sharesight 逐仓合计的金额差和百分比。不得称为 IBKR 实时逐仓数据。
5. 合格回退可用于逐仓表及其直接衍生指标；对账差必须展示，不得为了凑平而改数。若差异无法解释，相关衍生指标标为「待核实」，报告其他已验证部分照常发布。
6. 若 Sharesight `IB-HK` 不可读、超过上述一个交易日上限，或无法确认组合范围，仍须发布降级报告：逐仓表与依赖逐仓的指标标「本期不可用」，或沿用上一份可信值并逐项写明原日期；不得填零、猜数或把旧值写成当前值。

因此，`get_account_positions` 的单点故障、合格的 Sharesight 一交易日时差、或逐仓栏目暂不可用，均**不得成为整份报告停发或手机固定页不更新的唯一理由**。

## 4. 固定手机链接

定时版、Run now、补跑和临时版全部通过同一条安全链发布：候选分支 → Validate → Promote → Pages。任何通过验证的新报告都更新同一个手机固定链接。

手机显示“最新一份通过验证的报告”。后台分别保存并核验 AM、PM 历史；临时版可以成为手机最新页，但不能冒充定时版成功。

## 5. 临时报告启动口令

在 Claude 中运行专用任务 `XUAN-IB 临时报告（随时运行）`，或发送：

> 立即生成并发布一次 XUAN-IB 临时报告到手机固定链接。使用当前可取得的数据，逐项注明 as-of 时间，不进行任何交易操作。

临时报告报头必须含“临时版”或 `ad hoc`，不得含会让看护误判为 AM/PM 成功的标签。

## 6. 验收边界

1. 周一晚、周二早、周五晚、周六早、周日与临时加跑均有回归测试。
2. 21:25 HKT 看护周一至周五睡前版；08:35 HKT 看护周二至周六早间版。
3. 临时版之后仍能从 Git 历史证明同日应有的 AM/PM 已发布。
4. `index.html`、`latest.html`、metadata、`main` 与 Pages 的 hash/receipt 必须配对。
5. 模拟 `get_account_positions` 连续失败、其余四项 IBKR 读取正常且 Sharesight `IB-HK` 落后 0 或 1 个已完成美国交易日：报告必须使用带来源与日期标注的逐仓回退并成功进入发布链。
6. 模拟逐仓端点与 Sharesight `IB-HK` 同时不可用或后者过期：报告仍须发布降级版，逐仓及其衍生字段不得填零或猜测；看护不得把该单项降级误报为整份 PM / AM 缺失。
