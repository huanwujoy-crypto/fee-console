# XUAN-IB 香港时间报告契约 v1

> 本文件只规定报告时间、版次、日期语义与发布路径，不改变任何投资计算、持仓分类或风险参数；不授权下单、改单、撤单或转账。

## 1. 报告日期与调度时区

报告日期和手机时间仍使用 `Asia/Hong_Kong`。早间版保持香港固定时间；睡前版按 `America/New_York` 周一至周五 09:30，即美股正常开盘时启动：美国夏令时为香港 21:30，冬令时为香港 22:30。开市即启动不等于开市瞬间已完成报告；实际启动至公开页核验不超过 20 分钟即通过，仍尽可能缩短耗时。必须用 IANA 命名时区转换，不得按月份猜测 DST 或全年固定 UTC/HKT 偏移。

唯一计算源是纯模块 `scripts/xuan-ib-report-schedule.mjs`，供手机 loader 和只读看护共用。它计算报告时段，不证明市场已开市或金融数据已更新；开市、休市和提前收市状态仍须核对正式交易日历。变更仅在受控维护发布、原 Claude Routine 配置及 `Next run` 读回一致后启用；本文件不等于已经修改真实日程。

本次开市启动／20 分钟规则的切换日为 `2026-09-06`（HKT，`PM_OPENING_CUTOVER_HKT_DATE`）。保留两段历史：9 月 4 日以前为香港 20:55 启动／21:25 到期；9 月 4–5 日为纽约 09:35 启动／09:45 到期。原 `PM_SCHEDULE_CUTOVER_HKT_DATE` 保持 9 月 4 日，不追改旧报告。若发布延误，实际启用和缺失的验收必须明确披露，不得误称真实日程已切换。

真实配置限制：2026-09-04 实测 Code Routine 编辑界面只有本地时间／UTC cron，未见命名时区入口，且注明调度可能错峰。若启用时仍如此，先维护本季唯一 UTC 时段（夏令 13:30、冬令 14:30），在 DST 转换前受控改时并核验 `Next run`；在切换机制验收前不得声称 Routine 已自动适配 DST。不要仅凭运行时当前时钟同时启用两个季节候选：延迟启动可能落入另一个窗口，造成重复取数或发布。下述双季节看护可依据 GitHub 提供的 cron 身份去重，与 Routine 的能力不同。

### 2.1 二十分钟验收与延迟的区分

- 分别记录 `plannedStart`、实际 `startedAt`、候选准备、Validate、Promote、Pages 完成及公开页面精确读回时间。调度延迟＝实际启动−计划启动；报告耗时＝合格公开页读回−实际启动；另列计划启动至读回总耗时。未有证据的阶段不得填零或编造时间。
- 手机静态到期参考是计划启动后 20 分钟（纽约 09:50），看护在 09:55 观察。这只能发现计划交付延迟，不能独自证明实际运行超过 20 分钟。Claude 调度可能 stagger／排队；20 分钟是可核验的工程目标（SLO），不是硬性 SLA。手机验收耗时另列，不冒充报告生成时间。
- 预算参考：准备 0.5 分钟、并行读取至第 4 分钟、对账计算至第 5 分钟、固定模块渲染至第 6 分钟、guard／候选推送至第 7 分钟、Validate→Promote→Pages 至第 9 分钟，最后 1 分钟公开精确读回。实测超时须诚实记录，仍保留上一可信报告，允许后续合格迟到版发布，不得放松发布门禁。
- 继续遵守 runtime contract：IB 两波 `2+3`，七家族 Sharesight `3+3+1` 和两家辅助组合；所有要求的实时读取仍须执行。只重试失败端点且有界；批准的字段级回退可用但须带日期。hash 只复用未变规则或完整输入／身份／as-of／方法均一致的计算，不能替代实时读取。不要为追求时限，遗漏来源、将未知填零或重写长篇不变内容。20 分钟验收不延长 source arm 或当前有界账户关联期，也不恢复已取消的临时版。
- 保持已有事件驱动 Validate→Promote→Pages。每 15 分钟 Promote cron 只是后备，不能作为十分钟交付保证；不新增重复后台通知任务。
- scheduled 看护按 cron 身份固定查 AM 或 PM，延迟至另一版次之后也不能改查另一版来掩盖漏发。GitHub cron 表达式不提供原计划日期；多日积压时，最近到期同版的健康结果不是原计划准时交付证明，须另外按实际运行记录核对原日期，不得声称零延迟或已满足十分钟。

## 3. 报告日期与数据截止

- 报头日期是报告生成时的香港日期。
- 早间版另外明确写“对应美股交易日”或“美股休市，沿用最后可信收盘”。
- 每个主要来源分别标注 `as-of` 时间；不同来源时间不一致时不得假装同步。
- 美国市场状态必须由 `America/New_York` 时区和交易日历判断，不得按月份猜夏令时。
- 数据源失败时不得填零或猜数；按字段降级、保留上一份可信值并显著标注来源与日期。只有多个关键来源同时失效、无法确认账户范围，或候选 / Validate / Promote / Pages / 线上读回失败时，才按既有 fail-closed 规则停发。

`get_account_positions` 单一端点在有界重试后仍失败，属于**字段级数据源降级**，不得单独阻断 PM、AM、Run now、补跑或 ad hoc 报告的生成与发布。

2. IBKR 继续作为 NAV、现金、保证金、挂单和成交的权威来源；不得用 Sharesight 覆盖这些字段。
3. 逐仓数量、价格与市值可改读 Sharesight 的精确组合 `IB-HK`（portfolio id `936247`）。仅当其 `as-of` 不早于报告截止时已完成的最近一个美国交易日，或最多落后一个**已完成的美国交易日**时使用；周末与美国休市日不增加数据年龄。

因此，`get_account_positions` 的单点故障、合格的 Sharesight 一交易日时差、或逐仓栏目暂不可用，均**不得成为整份报告停发或手机固定页不更新的唯一理由**。

## 4. 固定手机链接

定时版、Run now、补跑和临时版全部通过同一条安全链发布：候选分支 → Validate → Promote → Pages。任何通过验证的新报告都更新同一个手机固定链接。
