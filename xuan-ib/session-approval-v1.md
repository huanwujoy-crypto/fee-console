# XUAN-IB 会话代发维护批准 v1（SESSION-APPROVAL-V1）

本文件放在 `xuan-ib/` 下仅为落入发布锁保护名单。它不是报告、候选或页面，
不参与任何 handover 候选提交，也不含账户余额、持仓、凭据或会话链接。

## 1. 生效条件（唯一身份锚点）

本通道只在下列条件全部满足后生效：引入本文件的 PR 由仓库所有者**以本人
GitHub 账号亲自**评论与当时 head SHA 完全一致的 `/approve-xuan-ib-maintenance
<sha>`，且 `xuan-ib-policy-lock` 与其余必需检查在同一 head 通过并合并到 main。
这条评论不得由 Claude、Codex、浏览器控制或任何代理代发。生效前经会话给出的
"接受""可以""同意"都不是批准，也不能事后追认。

## 2. 通道定义与范围

所有者在当前 Claude 会话中逐 PR 给出完整 40 位 head SHA，Claude 通过现有
OWNER 身份的 GitHub 连接器代发精确 SHA 评论。发布锁本身不变。适用于需要
OWNER 评论的受锁维护 PR，不含第 6 节排除项；不适用于 handover 候选、
fee-console 数据写入或任何金融系统操作，不授予任何金融、账户范围、系数、
阈值、日程、模型、连接器或通知权限。

## 3. 触发格式

只受理当前会话内满足全部要求的一条消息：含 PR 号与该 PR 当前 head 的完整
40 位十六进制 SHA；一条消息一个 PR 一个 SHA；不含"最新一版""全部""以后都"
等指代或批量措辞；不带"用户说""Codex 转述"等转述前缀，也不自述为转述；
在 Claude 已于本会话报出该 PR 的 head SHA 与变更摘要之后发出。缺任一项，
Claude 不代发，只回复缺什么。

## 4. 核对与动作（仅对该 SHA，仅一次）

Claude 先读取本文件；核对 SHA 等于该 PR 当前 head；确认已完整读过该 head 的
diff 并给出过摘要，草稿阶段检查无失败，本地已运行受影响的测试；按第 5 节
措辞代发评论；标 Ready for review；所有必需检查在同一 head 全绿且 head
未变时以普通 merge 合并；任何失败即停止并回报，不修改、不合并。

## 5. 代发评论固定措辞

```
/approve-xuan-ib-maintenance <40 位 head sha>

来源声明（SESSION-APPROVAL-V1）：本评论由 Claude 依据会话内批准代发。
发出账号为仓库所有者账号，但本人身份未经独立核验。批准指令来自 Claude
会话 <会话链接>，UTC 时间 <时间>，原文：「<触发消息原文>」。
本批准仅对上述 SHA 有效；任何新 commit 自动作废，须重新批准。
依据：xuan-ib/session-approval-v1.md。
```

禁止写"已验证本人""所有者亲自批准"或任何暗示身份已核验的措辞。

## 6. 永久排除项（仍须所有者本人亲自评论）

修改 `.github/` 下任何内容；修改本文件或 `claude/xuan-ib-maintenance-approval-v1.md`，
或改变本通道的格式、范围、措辞、排除项、有效期（含续期）；涉及仓库权限、
分支保护、环境、密钥、连接器身份或 GitHub 账号；扩大账户关联范围或续延其
有效期、新增 AI 压力系数或阶梯、改变风险阈值、日程或模型。对这类 PR，
Claude 只报出 head SHA 与摘要，然后等待本人评论。

## 7. 身份保证弱点（所有者知悉并接受）

发布锁看到的仍是 OWNER 账号，真实来源是"谁控制了这个 Claude 会话"，锁通过
不构成本人身份证据；独立于会话的 GitHub 登录这一第二因素消失；经授权的
浏览器控制、转贴或任何持有会话者发出的消息与本人输入无法区分；能向会话
写入的主体可构造合格批准，格式要求拦不住持有会话控制权者；"谁说了批准"
的原件只在 Anthropic 保管的会话记录中，评论里的声明是摘录；若批准经代理
进入会话，信任面并未缩小。所有者接受以上风险作为免于亲自操作 GitHub 的代价。

## 8. 有效期、撤销、作废

有效期自合并进 main 起至 2026-12-18 21:30 HKT（不含），到期自动失效；续期是
新的 PR，须按第 1 节亲自评论，Claude 不得自行续期。所有者在任何渠道说
"停止会话代发"即时生效，撤销不要求身份核验；恢复须重新按第 1 节启动。
新 commit 或 force push 改变 head，发布锁会自动拒绝旧评论。base 分支变化
与 PR 关闭重开不改变 head，现有锁可能不会自动识别，仍会接受同一 head 的
旧评论；此时程序必须视该批准为失效并重新索取完整 SHA 的批准，不得以锁
仍为绿作为继续的依据。

## 9. 审计与边界

每条代发评论含固定短语 `来源声明（SESSION-APPROVAL-V1）`，搜索即可枚举本
通道生效后的代发批准。不能仅凭缺少该短语判断某条 OWNER 评论出自本人：
代理此前也可能以 OWNER 账号发过评论，历史评论须按独立证据逐条核验。
本通道不修改发布锁、工作流、权限或分支保护；不下单、改单、撤单、转账，
不写 IB、Sharesight 或任何金融账户；不构成任何 AM／PM 运行成功的证据，
不改变已发布页面、标签、回执或决定。
