# Complete-original assembly candidate

This version adds `prepare_offline_performance(request, enabled=False)`. The
request is exactly the source-set API in PERFORMANCE-BOUNDARY.md. It does not
accept targets, a scope, an executable, module paths, a verifier, authentication
flags, or a clock from the caller. Disabled mode performs no source IO or
projection process launch.

## Completed local implementation

1. The existing boundary binds all ten workbook originals, five capture records,
   and the inception document/source bytes, retaining original freshness and
   complete member evidence requirements.
2. Combined Top5 rows are expanded against the exact primary account vocabulary
   and instrument/name/member set. Comma-containing names must have exactly one
   complete segmentation; normalized aliases cannot introduce duplicate members.
   Combined and grouping sheets cover every primary member exactly once.
3. Exact XML decimal price, quantity, value and H/J/L/N amount relationships are
   required. Missing patterns stay missing. This version deliberately refuses
   differing cross-capture values and historical tolerances. O return percentages
   are transcribed from native cells and never summed or reverse calculated.
4. Strategy scopes replace only the historically designated portfolio, strategy
   and secondary-market rows, after exact membership checks. The third source is
   reserved for the precise stock subtotal. Other source rows remain unchanged.
5. Portfolio return amount uses N on the same native row as O, with complete
   member amounts, H+J+L=N, exact cent precision and the original source reference.
   Missing amounts refuse assembly, rather than becoming zero or value times rate.
6. Top5 targets come only from the pinned allocation/company projection, not
   caller-selected names, workbook order, or a fabricated rank. Native source rows
   or exact native subtotals supply each target's return; the members, source
   coordinates and source units are retained. Unsupported targets are explicitly
   unavailable according to the established contract, never estimated.
7. The final `sharesight-private-performance-v1` original includes both native
   reports, stock/strategy source links, Top5 and the unchanged inception-v2
   declarations. The same pinned pure consumer checks its complete associations.

## Controlled pure projection dependency

Four unchanged repository modules are frozen under `adapter/projection_reference`
at code reference `6de56ffb708e8995edfc3b67895841ab474a2c02`. Their exact SHA-256
values are checked before and after the internal projection bridge. These are
existing application source files, including their existing scope policies and
labels, not private financial source records.

The bridge invokes the already installed Node binary at one fixed local path,
with no shell and an empty environment. NODE_OPTIONS, LD_PRELOAD, PATH hooks,
credentials and configurable executable/module paths are not inherited. No
network/publishing module is used. Inputs and outputs pass through private
subprocess pipes; no source file is rewritten.

This is validation against a pinned historical pure contract. It is NOT
verification against the current cloud HEAD, provider authentication, a signed
source attestation, a snapshot authorization or publication permission. Fixed
account policy is enforced by the Python source IO boundary; the pure JS helper
does not independently grant account authority.

Moving to another runtime requires a coordinated code change and checks, not a
request-supplied executable override. Missing Node or a changed code pin refuses
the operation. No package is installed and no failed source download is retried.

## Result and remaining blockers

Success is `OFFLINE_COMPLETE_ORIGINAL_CANDIDATE` with
`performanceAssembled=true` and `referenceContractValidated=true`.
`originalLibraryIdentityPending=true`: the newly assembled JSON has not acquired
its own genuine Library identity merely because its inputs were bound.

`sourceOriginVerified`, `fullPerformanceReady`, `publicationReady`,
`productionEnabled`, and `currentCloudCompatibilityValidated` remain false.

Remaining blockers are:
- Provider-observation authentication for the capture and inception assertions.
  Bound bytes and a valid declaration do not prove a remote page was complete.
- Integration and regression checks against the actual current cloud repository,
  preservation of its existing shared changes, and the requested independent full
  review once both development directions are complete.
- Existing refresh date policy and separately authorized activation/acceptance.

The previously listed combined-Top5 and final-assembly implementation gaps are
closed for this strict supported local path. Real source acceptance, all possible
report variations and current production compatibility have not been established.
