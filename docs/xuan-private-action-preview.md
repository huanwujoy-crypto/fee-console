# Private actual-data action preview

This candidate composes a private four-card preview after the separately reviewed
orders-only Cloud Run probe. Nothing in it runs by import, activates a schedule,
deploys a job, changes the normal report composition or publishes financial data.
The October 15 official backfill remains cancelled. An offline fixture is not a
real-data acceptance or proof that cloud OAuth recovered.

## Bounded actual-data acceptance

1. Review the complete candidate, obtain its final signed source and applicable
   exact-head OWNER approval/checks. Separately approve the bounded probe image
   build, one unscheduled job and one execution described in
   `xuan-cloud-orders-probe.md`. Establish the exclusive shared-credential window.
2. Run that current-date probe once. Only its fixed safe result may be logged.
   Fetch its new `receipt.json` and `orders.json` from the fixed private bucket
   under the exact request ID, pinning the returned generations and hashes. Use
   the existing authorized read identity only. If it lacks those reads, stop;
   do not add an IAM binding, substitute an old EOD context or create another ID.
3. Invoke `composePrivateActionPreview` from the controlled private controller
   with the fetched bundle and existing private IO. This is an exported API,
   not an additional unattended CLI/schedule. It verifies the receipt hash,
   source object hash/generation, request/execution, original association,
   account-response evidence and actual timestamps before any Sharesight read.
   Caller-supplied hashes alone do not authenticate a network origin; the
   controller must actually fetch the pinned private objects in step 2.
4. Read only the two fixed Sharesight IB-HK/NOAH-HK performance scopes through
   the existing cloud gateway. They supply cash, holdings and classifications.
   Validate actual portfolio IDs, grouping, currency and completed source date.
   The existing three-account sync schedule alone does not prove NOAH coverage
   or sync completion. Available producer receipts may be supplied through the
   existing verifier seam; without them the UI says date-verified, not synced.
5. The composer makes no IB call, refresh or Flex request. It reuses exactly the
   probe orders already obtained. The five-minute window starts at their actual
   source start; the program refuses a longer combined capture. Preserve the
   existing thirty-minute publication freshness gate. Never relabel an old
   website snapshot, including the seven-minute October 15 capture, as this run.
6. Save the model, source evidence, receipt and HTML only under the existing
   private destination. Inspect all four cards at phone width. This private
   model is not accepted for cleartext public publication; existing public
   projection and privacy checks remain in force.

## Financial dependencies and display

Sharesight book cash is separate from broker AvailableFunds. Historical Flex
reconciliation is optional in the field model and cannot erase current source
facts. Book planning remains reference-only, with executable budget unknown.
CALL uses the existing owner-provided ledger until the owner supplies a changed
level. Its declaration date is not an expiry or daily confirmation requirement.

BUY reserve uses remaining quantity times limit, never total order quantity or
filled quantity. SELL proceeds are excluded. The existing Sharesight book cash
is not reduced again for historical filled executions. Order rows can remain
visible with unknown total coverage, unknown currency or unavailable FX; those
conditions block complete reserve and dependent budget. Do not silently assume
USD or add native-currency market values. Native instrument currency can be
reused only when explicitly present and unambiguous in validated Sharesight
holdings. Missing facts stay missing; source/date/status is shown per field.

Source arrays and native scalar ranges are checked before mapping. Current
allocation, projected allocation, funding need and replenishment use the same
contribution validators at generation and final validation. A failed source or
derived contribution records a closed `fieldErrors` code in the private model
and its bound receipt, while its affected values stay unknown. In particular,
an invalid projection cannot discard valid cash/current allocation; an excessive
reserve is not zero. Cash-pool, cash-like and total-capacity sums have their own
range boundaries. The final whole-report integrity guard is still mandatory;
account, provenance/hash and capture-window failures are not swallowed as a
missing financial field. UI reasons use fixed text, never raw exception bodies.

## Phone review and remaining approval

A local private HTML preview is immediately possible after approved collection.
For a phone-accessible temporary release, use a verified existing owner-only
authenticated viewer if available. Otherwise a separately approved encrypted
owner-controlled viewer is required. No real viewing key, grant, persistent
permission, public cleartext page or production cutover is created here. Any
encrypted artifact must also be checked for metadata, log and browser leakage.

Needed user actions are concentrated: approve the final source head after review;
approve the specified one-shot build/job/execution and required existing-token
persistence; then approve a concrete private mobile delivery method if none is
already authorized. The temporary real-data preview is not a normal publication
or a guarantee that tomorrow's scheduled production report will succeed.
