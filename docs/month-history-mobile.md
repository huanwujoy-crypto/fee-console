# 月度明细 · 手机历史浏览契约

## 目标

月度明细需要长期保存全部月份，同时让 iPhone 首屏保持简洁。历史数据不得因页面只显示
最近月份而删除、截断或改写。

## 手机布局

1. **本月／最新月份**默认展开。月份导航以已验证 public ledger 的 `status.asOf`（并与
   `max(daily.d)` 一致）为准，不依赖手机当前 UTC 日期，也不依赖费用回执是否可用；月份行
   若晚于或未覆盖该 `asOf` 月，整个历史模型 fail-closed，不得静默隐藏矛盾后继续显示。
2. **历史月份（N）**作为一个总折叠区，默认收起；N 是保留的历史月份数。
3. 历史区使用 iOS 原生年份下拉框，默认选择 `asOf` 所在年份。
4. 选定年份内的月份按新到旧排列，每个月默认折叠。
5. 折叠行只显示“月份、净收益、总费用、状态”；展开后才显示期初／期末、资金流、毛收益、
   管理费、Carry、净收益、TWR、Modified Dietz 和公开 benchmark。
6. 图表默认只画最近 12 个月，并放入可折叠的“近期走势”；底层仍保留全部历史。
7. 付款历史采用相同原则：应付合计常显，逐笔历史默认折叠。

## 可用性与安全

- 年份下拉使用原生 `<select>`；所有折叠使用可键盘操作的 `<details>/<summary>`。
- 触点不小于 44px；状态同时使用文字与图标，不只靠颜色。
- 回执缺失、过期、无法验证或存在 unresolved flow 时，相关月份不得回退到旧公式，显示
  “计算回执待更新”；原始 AUM 和公开 benchmark 历史仍可按 public ledger 浏览。
- 上线前至少验证 1、36、120 个月数据量，以及窄屏、年份切换、刷新后默认状态和只读模式。
